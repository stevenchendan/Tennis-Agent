# YouTube 比赛复盘（Hybrid）+ 历史比赛列表

## Overview
Two additions that together form the "review" feature:

1. **YouTube ingestion (hybrid engine)** — a player pastes a YouTube link of a match they played (e.g. `https://www.youtube.com/watch?v=fTL3zWj997g`). A new `youtube` analysis mode downloads the video via **yt-dlp**, then analyzes it with whichever engine is available:
   - **CV engine** (if `TENNIS_BALL_MODEL_PATH` weights are set): identical pipeline to uploaded videos — YOLO tracking → rallies → pattern cards → stats → report.
   - **AI vision review** (no weights, but LLM key set): sample ~24 frames evenly from the video, downscale, and send to the multimodal LLM (`gpt-4o-mini` default) for a Chinese coach-style review report. Stages detect/map/events/tactics are marked SKIPPED; the report tab is the product.
   - Neither configured → honest 400 at creation time (matches the project's graceful-degradation philosophy).
2. **我的比赛 (game history)** — a list on the home page showing all previously analyzed games, so a player can select any game they played before and reopen its analysis. Includes a backend fix: `GET /api/analyses` currently only reads the in-memory job store, so history disappears after a backend restart — it will also scan persisted `data/analyses/*.json`.

## Backend changes

### 1. `backend/requirements.txt`
- Add `yt-dlp` (pure Python; ffmpeg optional — request progressive ≤720p mp4 so merging isn't needed).

### 2. `backend/app/core/config.py`
- `youtube_max_duration_min: int = 90` (0 = unlimited) — reject full broadcasts before downloading.
- `review_frame_count: int = 24` — frames sampled for the vision review.

### 3. NEW `backend/app/services/youtube.py`
- `is_available()` → yt-dlp importable.
- `parse_youtube_url(url) -> video_id | None` — accepts `watch?v=`, `youtu.be/`, `shorts/`, `embed/`; ignores playlist/timestamp params; `None` for non-YouTube/malformed.
- `probe(url)` → `{title, duration_s, uploader}` via `YoutubeDL.extract_info(download=False)`, errors mapped to friendly messages (private / age-restricted / unavailable).
- `download(url, dest_dir, max_height, on_progress)` → downloads mp4 into `data/videos/{id}_yt_{video_id}.mp4`; progress hook feeds the job's stage detail.

### 4. `backend/app/services/jobs.py`
- `YOUTUBE_STAGES = ["download", *STAGES]`; `JobStore.create(..., stages=None)` override.
- `AnalysisJob.engine: Optional[str]` (`"cv" | "llm_vision"`), included in `as_dict`.

### 5. `backend/app/domain/events.py`
- `AnalysisResult`: add optional `source_url`, `source_title` (mode value becomes `"youtube"`).

### 6. `backend/app/services/pipeline.py` + NEW `app/services/llm/vision.py`
- Split the post-ingest body of `run_full_analysis` into `_run_cv_stages(settings, job, video_path, source, mode)` for reuse.
- New `run_youtube_analysis(settings, job, url)`:
  - `download` stage: probe → duration guard → download with progress detail.
  - Weights present → CV stages via `_run_cv_stages` with `source = video title`.
  - Else → vision review: `llm/vision.py` samples frames via existing cv2 streaming (`yolo.iter_frames`), downscales to ≤768px JPEGs, base64 data-URLs into a multimodal LangChain chain using the existing `get_chat_model()`; prompt asks for a structured Chinese coach review (整体评价 / 技术亮点 / 战术问题 / 改进建议 / 训练重点). `report_generated_by = "llm_vision"`; LLM failure fails the job (no heuristic fallback possible for video understanding — unlike the CV path, the report is the only output).
- Sets `source_url`/`source_title` on the result for both engines.

### 7. `backend/app/api/routes.py`
- `CreateAnalysis.youtube_url`; `mode: "youtube"` validates: URL parses, yt-dlp available, and (ball weights **or** LLM key) — clear 400 messages otherwise.
- `_run_job` dispatches youtube; `job_store.create(mode="youtube", stages=YOUTUBE_STAGES)`.
- `GET /api/health` adds `youtube_ready`.
- `GET /api/analyses` merges in-memory jobs with persisted analysis JSON (new `storage.list_persisted_summaries`) so history survives restarts.

### 8. Tests — NEW `backend/tests/test_youtube.py` (+ small `test_api.py` additions)
- URL parsing cases (valid forms / rejects non-YouTube).
- API 400s: bad URL, yt-dlp unavailable, no engine configured (monkeypatched; no network).
- Mocked download + mocked vision chain → job `done`, `report_generated_by == "llm_vision"`, detect/map/events/tactics skipped.
- Duration guard → failed job with friendly error; history merge shows persisted file.

## Frontend changes

### 9. `frontend/src/lib/api.ts`
- `createYoutubeAnalysis(url)`, `listAnalyses()`; health type += `youtube_ready`; `AnalysisResult` += `source_url?`, `source_title?`.

### 10. `frontend/src/app/page.tsx`
- New **YouTube 链接复盘** input + submit button (paste URL → create analysis → navigate to `/analyses/{id}`), with requirement hints derived from health flags (e.g. “未配置 YOLO 权重，将使用 AI 视觉复盘（需要 LLM key）”).
- New **我的比赛** history section: fetches `GET /api/analyses` on mount, lists mode/status/title/date, click opens the analysis.

### 11. `frontend/src/components/StageProgress.tsx`
- Add label `download: "下载"` (component already falls back to raw names, but proper label is better).

### 12. `frontend/src/app/analyses/[id]/page.tsx`
- Header: clickable source link to YouTube when `source_url` present.
- Vision-review results (`report_generated_by === "llm_vision"`): hide/empty-state the stats strip and patterns/rallies tabs (“AI 视觉复盘不含逐拍数据；配置 YOLO 权重可获得完整分析”); running view shows the video title/URL.
